WINDSURF MASTER PROMPT FILE
10 Full Stack Web Development Projects
React.js  ·  Node.js / Express.js  ·  MongoDB Compass  ·  Tailwind CSS  ·  Axios
HOW TO USE THIS FILE
Open Windsurf IDE.
Create a root workspace folder (e.g. NESA_Projects).
For each scenario below, create its folder (e.g. scenario-1-SLMS) inside the workspace.
Open that folder in Windsurf, then paste the scenario's prompt into the AI chat.
The AI will scaffold both backend-project and frontend-project inside the scenario folder.
Repeat for every scenario independently.
  GLOBAL TECH STACK & RULES  (applies to ALL 10 scenarios)  
Stack
Frontend : React.js (Vite), React Router DOM, Axios, Tailwind CSS
Backend  : Node.js, Express.js, Mongoose (MongoDB ODM), CORS, dotenv, nodemon
Database : MongoDB — use MongoDB Compass to view data (NO MySQL)
Auth     : Simple session-based login stored in localStorage (no JWT needed)
Folder structure inside each scenario folder
scenario-X-CODE/
  backend-project/
    models/
    routes/
    server.js
    .env
    package.json
  frontend-project/
    src/
      components/
      pages/
      api/
      App.jsx
      main.jsx
    index.html
    package.json
Backend rules
server.js imports express, cors, mongoose, dotenv.
Connect to MongoDB with: mongoose.connect('mongodb://localhost:27017/CODE')
Port: 5000. Use nodemon for development.
One route file per entity (e.g. routes/students.js).
Full CRUD only on the LAST (transaction) entity. INSERT only on the other two.
Frontend rules
Vite + React. Tailwind configured in tailwind.config.js and imported in index.css.
React Router DOM v6 — one page per entity + Reports page + Login page.
Axios base URL set to http://localhost:5000 inside src/api/axiosConfig.js.
Simple, clean UI — white cards, blue accents, readable fonts. NOT over-engineered.
Login page stores { username, loggedIn:true } in localStorage. Logout clears it.
Navbar shows the nav links for that scenario (listed in each prompt below).
Seed data
Manually insert seed data via MongoDB Compass after the server starts, OR add a simple seed script.
  SCENARIO 1 — Student Library Management System (SLMS)  
  Folder: scenario-1-SLMS
Context
ReadNest is located in Musanze District, Northern Province of Rwanda. It uses a paper-based system to manage book borrowing and returning, which causes delays and frequent loss of book records. A web-based application is needed so staff can manage records digitally and generate reports automatically.
Windsurf Prompt — paste this into AI chat
You are helping me build a simple full stack web application called the Student Library Management System (SLMS).
 
== TECH STACK ==
Frontend : React (Vite) + Tailwind CSS + React Router DOM + Axios
Backend  : Node.js + Express.js + Mongoose + CORS + dotenv + nodemon
Database : MongoDB (local, port 27017, db name: SLMS)
 
== FOLDER STRUCTURE ==
Work inside the folder: scenario-1-SLMS/
  - backend-project/   (Express + Mongoose API)
  - frontend-project/  (React + Vite + Tailwind)
 
== DATABASE COLLECTIONS ==
Collection 1: Student — fields: studentId, firstName, lastName, gender, className, telephone, address
Collection 2: Book — fields: bookId, title, author, category, quantity
Collection 3: Borrowing — fields: borrowId, borrowDate, returnDate, status, fine, studentId*, bookId*
 
Foreign keys marked with * mean that field stores the _id of the related document.
 
== SEED DATA (insert into MongoDB Compass after server starts) ==
Collection: Book
categoryCode | categoryName | totalBooks | available
SC | Science | 5 | 3
LT | Literature | 3 | 1
MT | Mathematics | 8 | 5
HY | History | 4 | 2
 
== BACKEND REQUIREMENTS ==
1. server.js: import express, cors, mongoose, dotenv. Connect to mongodb://localhost:27017/SLMS. Listen on port 5000.
2. Create a Mongoose model file in models/ for each collection.
3. Create a route file in routes/ for each collection.
4. Routes for Student and Book: POST (create) only.
5. Routes for Borrowing: GET all, POST (create), PUT (update by id), DELETE (by id).
6. Also create a Users collection with POST /api/users/login that checks username+password.
 
== FRONTEND REQUIREMENTS ==
1. Login page: simple form (username, password). On success save {loggedIn:true} to localStorage and redirect.
2. Navbar with links: Login, Students, Books, Borrowing, Reports, Logout.
3. Page for Student: form to add a new student. Show a table of all existing records (GET).
4. Page for Book: form to add a new book. Show a table of all existing records (GET).
5. Page for Borrowing: full CRUD — form to add, table showing all records, edit button (pre-fills form), delete button.
6. Reports page: fetch all borrowing records joined with related data and display as a styled table.
   Report columns: monthly borrowing report: StudentName, BookTitle, BorrowDate, ReturnDate, Fine.
7. Logout: clears localStorage and redirects to Login.
8. Axios config: create src/api/axiosConfig.js with baseURL http://localhost:5000.
 
== STYLE GUIDE ==
- Simple and clean. White background, blue (#2563EB) accents, gray borders.
- Tailwind utility classes only. No external UI libraries.
- Responsive: works on desktop and tablet.
- Each form inside a white card (shadow, rounded corners, padding).
- Tables: striped rows, header row with blue background and white text.
 
== WHAT TO GENERATE ==
Generate ALL files needed to run the project:
backend-project: package.json, .env, server.js, models/*.js, routes/*.js
frontend-project: package.json, vite.config.js, tailwind.config.js, postcss.config.js,
  index.html, src/main.jsx, src/App.jsx, src/index.css,
  src/api/axiosConfig.js, src/pages/*.jsx, src/components/Navbar.jsx
 
After generating, tell me the exact commands to run:
  cd scenario-1-SLMS/backend-project && npm install && npm run dev
  cd scenario-1-SLMS/frontend-project && npm install && npm run dev
